Why this design: conversation IS the product. The vehicle context (year/make/model/trim, mileage, issues, recalls, parts cache count) lives in the left rail and follows the user across every interaction. Issues, recalls, parts, and Drive routes surface as rich attachments inside the conversation instead of as separate pages. Same vehicle context flows from chat → Drive → known-issues lookups via the persistent rail.

What's mocked vs real: all data is hardcoded for this prototype (vehicle, issues, recent threads, map, attachments). Backend wiring would use the existing ChatSession Prisma model, the KnownIssue table, and Mapbox routing for the inline trip preview.

Anonymous gate: toggle the view switcher above to see how the same surface presents to a signed-out user — limited message count + "Sign in to save" CTA. No data is persisted for anonymous sessions, keeping AI spend bounded.
